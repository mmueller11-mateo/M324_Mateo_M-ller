# 11e - GitHub Releases, Tags & Deployment

## 1. Inhalt und Relevanz der Website
* **Was macht die Website?** 
  Meine Website ist ein persönliches kleines Informatiker-Portfolio / eine Informationsseite. Sie stellt kurz mein Profil vor, zeigt aktuelle Schul- bzw. Betriebsprojekte und bietet schnelle Verlinkungen zu meinen wichtigsten Ressourcen.
* **Warum ist sie relevant für mich?** 
  Sie dient mir im Alltag als Übungsobjekt, um das Erstellen und Veröffentlichen von statischen Webseiten praxisnah zu testen. Zudem verstehe ich dadurch, wie aus lokalem Code über GitHub Pages automatisch eine öffentlich erreichbare Webseite entsteht.

## 2. Einbindung einer Datenbank
Da GitHub Pages ein reines **Hosting für statische Dateien** (HTML, CSS, JavaScript) ist, kann dort keine serverseitige Datenbank (wie eine lokale MySQL- oder PostgreSQL-Datenbank) direkt betrieben werden.

Um trotzdem eine Datenbank einzubinden, gibt es folgende Möglichkeiten:
* **Backend-as-a-Service (BaaS):** Nutzung externer Cloud-Dienste wie **Supabase** oder **Firebase**. Das Frontend (JavaScript auf der GitHub-Pages-Seite) kommuniziert dabei über HTTPS/REST-APIs direkt mit der Cloud-Datenbank.
* **Eigener API-Server:** Hosting eines separaten Backends (z. B. Node.js, Python/FastAPI oder C#) auf einer Plattform wie Render, Fly.io oder Azure. Das Frontend schickt Anfragen an diesen Server, welcher die Datenbankabfragen durchführt.

## 3. Deployment nur bei neuem Tag (Tag-Triggered Deployment)
* **Ist das möglich?** 
  **Ja, das ist möglich.**
* **Erklärung / Umsetzung:**
  Wenn man GitHub Pages über das Standard-Menü (*Deploy from a branch*) nutzt, wird bei jedem Push auf den `main`-Branch automatisch neu gebaut. 

  Um das Deployment ausschließlich an neue Tags zu binden, stellt man die Deployment-Quelle in den Repository-Einstellungen unter **Pages** auf **GitHub Actions** um und erstellt einen eigenen Workflow (`.github/workflows/deploy.yml`):

  ```yaml
  name: Deploy to GitHub Pages on Tag

  on:
    push:
      tags:
        - 'v*' # Löst das Deployment nur aus, wenn ein Tag wie v1.0.0 gepusht wird

  jobs:
    deploy:
      runs-on: ubuntu-latest
      steps:
        - name: Checkout Repository
          uses: actions/checkout@v4

        - name: Setup Pages
          uses: actions/configure-pages@v4

        - name: Upload Artifact
          uses: actions/upload-pages-artifact@v3
          with:
            path: '.'

        - name: Deploy to GitHub Pages
          uses: actions/deploy-pages@v4
